# desktop bridge contract

A localhost-only browser UI for cecli that talks to `cecli --acp` over stdio.
The Python bridge and the HTTP/SSE payloads below are the contract; the UI is a
Lit client built from `ui/` with Vite.

## Runtime layout

```
desktop/
  server.py            Python 3.10+ stdlib only; HTTP + SSE <-> ACP stdio bridge
  ui/index.html        Vite entry document
  ui/vite.config.js    root=ui/, dev proxy for /api, build output ../static
  ui/src/main.js       module entry; starts the SSE session
  ui/src/core/         store, reducers, SSE events, snapshot, API, markdown, format
  ui/src/components/   Lit light-DOM components (no Shadow DOM)
  ui/src/styles/       Tailwind/daisyUI entry and component-scoped CSS
  static/index.html    generated by `npm run ui:build`
  static/assets/       generated, content-hashed JS and CSS bundles
  tests/               optional test fixtures
  README.md            user documentation
```

The UI uses Lit, Tailwind CSS v4 and daisyUI. Vite compiles `ui/` into
`static/`; the bridge serves `static/index.html` at `/` and the hashed bundles
under `/static/assets/`. Run `npm run ui:build` in `desktop/` after changing
`ui/`. Python needs no Node at runtime once `static/` has been built, and the
page makes no external requests: all framework code is bundled.

The server never requires third-party packages. The browser app never loads
external fonts, scripts, or styles.

## ACP facts the bridge relies on

cecli speaks newline-delimited JSON-RPC 2.0 on stdin/stdout when launched as
`cecli --acp`. stdout carries protocol only; stderr carries logs.

Handshake order:

1. `initialize` request `{"protocolVersion": 1, "clientCapabilities": {}}`
2. `session/new` request `{"cwd": "<absolute workspace>", "mcpServers": []}`
the session/new response is deferred until the coder is ready and contains
`{"sessionId": "...", "configOptions": [...], "modes": {...}}`.
3. `session/prompt` request `{"sessionId": "...", "prompt": [{"type": "text", "text": "..."}]}`
   The response `{"stopReason": "end_turn" | "cancelled"}` arrives when the turn ends.
4. `session/cancel` notification `{"sessionId": "..."}` (no id, no response).
5. `session/set_config_option` request `{"sessionId": "...", "configId": "mode", "value": "..."}`
   Config options look like `{"id", "name", "category", "type": "select",
   "currentValue", "options": [{"value", "name", "description"} | {"group", "name", "options": [...]}]}`.
   While a turn runs, a `cecli/steer` request with the same `sessionId` and `prompt`
   injects the text into that turn instead of starting another. It returns
   `{"ok": true, "steered": true}` and emits a `session_message` update with
   `userMessage: true`.

Server-to-client requests: `session/request_permission` with
`{"sessionId", "toolCall": {"toolCallId", "content": [...]}, "options": [{"optionId", "name", "kind"}]}`.
Kinds are `allow_once`, `allow_always`, `reject_once`, `reject_always`.
Reply with result `{"outcome": {"outcome": "selected", "optionId": "<id>"}}`
or `{"outcome": {"outcome": "cancelled"}}`.

Notifications: `session/update` with `{"sessionId", "update": {...}}`. Update kinds:

- `agent_message_chunk` `{content: {type: "text", text}}` — append to assistant text
- `agent_thought_chunk` `{content: {type: "text", text}}` — append to reasoning text
- `tool_call` `{toolCallId, title, kind, status, rawInput?, content?, locations?}`
- `tool_call_update` `{toolCallId, status?, title?, content?, kind?}`
- `tool_call_content_chunk` `{toolCallId, content: {type: "text", text}}`
- `plan` `{entries: [{content, priority, status}]}` where status is
  `pending` | `in_progress` | `completed`
- `usage_update` `{used, size, cost?: {amount, currency}}`
- `config_option_update` `{configOptions}`
- `current_mode_update` `{currentModeId}`
- `state_update` `{state, stopReason?, scope?}` where state is `running` | `idle` |
  `requires_action`; `scope` names the cached detail that changed (`skills`, `hooks`,
  `mcp`, `workflows`, `context`), so the client can refresh it without polling
- others (`session_message`, `subagent_update`, ...) must be ignored gracefully.

Tool `content` entries look like `{"type": "content", "content": {"type": "text", "text": "```\n...\n```"}}`.
Treat tool content as untrusted text.

## Server CLI

```
python3 desktop/server.py [--host 127.0.0.1] [--port 8765] [--workspace DIR]
                          [--cecli PATH] [--open] [-- extra cecli args...]
```

- `--workspace` defaults to the current directory and is resolved to an absolute path.
- `--cecli` defaults to `$CECLI_BIN`, then `shutil.which("cecli")`, then `"cecli"`.
- The child command is `[cecli, "--acp"] + extra_args`, launched with `cwd=workspace`.
- Bind loopback only by default; warn if `--host` is not a loopback address.
- Print the listening URL on startup.
- Handle SIGINT/SIGTERM by terminating the child and exiting cleanly.


## SSE events

`GET /api/events` responds with `Content-Type: text/event-stream`,
`Cache-Control: no-cache`, `Connection: keep-alive`, `X-Accel-Buffering: no`,
sends `retry: 2000`, then JSON on unnamed `data:` lines:

```
data: {"type": "status", "status": "ready"}

```

Event types:

- `status` — `{status: "starting"|"ready"|"exited", detail?, agent?}`
- `session` — `{sessionId, configOptions, modes}`
- `update` — `{sessionId, update}` (raw ACP update, pass-through)
- `permission` — `{requestId, sessionId, toolCall, options}`
- `permission_resolved` — `{requestId, optionId}` (`optionId` null when dismissed)
- `prompt_done` — `{stopReason}`
- `log` — `{message, level}` (child stderr, server notices)
- `error` — `{message}`

On connect, immediately send the current `status` and, if a session exists, a
`session` event so a late or reconnecting client can render itself.
Pending permission requests are replayed the same way, so reloading the page
during an approval does not strand the turn.
A heartbeat comment `: ping` goes out every 15 seconds. Remove dead clients.

## Behaviour requirements

- One cecli child and one session per server process. Start the child on
demand (first API use) or at boot; either is fine, but `/api/state` must
report the truth.
- Queue nothing: a prompt while busy is rejected with 409. The UI disables send.
- When the child exits, resolve open permission requests as cancelled, emit
  `status exited`, and reject further prompts with 409/503.
- `session/cancel` must be a notification (no id), then the outstanding
  `session/prompt` response reports `cancelled`.
- Permission request ids are the JSON-RPC ids, which may be numbers or strings.
- Requests from the child that are not `session/request_permission` must be
  answered with a JSON-RPC error (method not found) rather than hanging.
- Never block the event loop on subprocess I/O; use asyncio subprocesses.
- Cap request bodies (e.g. 1 MiB) and return 413 beyond that.
- Reject `Transfer-Encoding` requests (chunked bodies are unsupported) with 400.
- Require `Content-Type: application/json` on `/api/*` POSTs and return 415 otherwise.
- Reject requests whose `Host` is not the bound host or a loopback name, and
  reject cross-origin `Origin` values, both with 403. These stop DNS-rebinding
  reads and plain-text cross-site POSTs against the local bridge.
- Escape nothing server-side; the UI escapes all text it renders.

## UI requirements

- Clean, light chat layout: soft lavender wash, white surfaces, subtle borders,
  a centred transcript, and a left sidebar for sessions, sub-agents, and registries.
- Header: brand, workspace path, connection status. Before the first turn the
  transcript shows a large empty state with the cecli ASCII wordmark (the same
  art as the cecli.dev hero, without its tagline), a short greeting, and example
  prompt chips.
- Control strip under the composer: config select chips for the ACP config
  options (mode, model, effort, ...), a compact context-usage badge, and icon
  buttons for logs, new chat, and restart. Logs open as a popover above the
  strip. Responsive down to 720px; usable at 380px, where the strip wraps.
- Transcript items: user message, assistant message (streamed, small blinking
  cursor while busy), collapsible thoughts, tool cards with status chips and
  expandable output, plan checklist, permission cards with option buttons,
  error notices. Auto-scroll unless the user scrolled up.
- Composer: Enter sends or steers the running turn when busy, Shift+Enter
  newlines; the send button becomes Stop when the composer is empty while a turn
  runs. Show stop/retry affordances.
- Render a safe subset of markdown: fenced code, inline code, bold, italic,
  headings, links (http/https only), ordered/unordered lists, blockquotes.
  Always escape HTML first.
- No external network requests from the page at runtime. Lit, daisyUI and
  Tailwind are bundled at build time; there is no CDN.
- Sub-agent pills above the composer switch the transcript between the primary turn
  and each discovered child session; child text, thoughts, tools and plans stream
  into their own transcript while the sidebar keeps the agent tree fresh.
- New-session, model and registry actions use modals: the sidebar `+` asks for
  workspace path and title, the model chip opens a searchable model picker, and
  the Skills, MCP and Context badges under the composer open their registries.
- Workflows are listed in a dedicated sidebar section below the session tree;
  each row runs `/workflows run <name>` in the active (primary) session.
- The desktop always runs in agent mode; there is no mode switcher or
  reasoning-effort selector. Mode changes are refused by the bridge, and effort
  stays under the agent's control (`/reasoning-effort` still works).
- The composer offers bridge completion candidates for `/` commands, command
  arguments, `@` mentions and paths; Arrow keys move, Tab/Enter accept, Esc closes.
- Reconnect to `/api/events` automatically with backoff; resync state on open.
- A right-hand workbench column keeps a live Chrome/Chromium preview above a
  background-command panel. The browser streams real pages over SSE and forwards
  pointer, wheel, text and key input; the command panel mirrors the TUI's active
  tabs, command line, output and Follow control. Chat and workbench split the
  remaining width evenly, and header toggles hide the sidebar, chat, or workbench.
  The tab strip scrolls horizontally without a visible scrollbar, offers new-tab
  and hover-close controls, and the browser, background, and workflows headers
  each collapse their own section when clicked. The column hides below 940px.
- Keyboard accessible; permission buttons reachable by tab; `Esc` cancels a turn
  when the composer is not focused.

## Browser preview bridge

`desktop/browser_bridge.py` drives an installed Chromium browser over the
Chrome DevTools Protocol so the UI can show real pages that refuse framing or
need a real cookie jar. It is standard-library only and never exposes CDP past
loopback.

- Discovery: `CECLI_BROWSER_BIN` first, then `shutil.which` for Chrome, Edge,
  Chromium and Brave, then the usual Windows, macOS, Linux and WSL install
  paths (including `/mnt/c/Program Files/Google/Chrome/Application/chrome.exe`).
  Chrome is preferred.
- Profile: `~/.cecli/desktop/browser-profile`, override `CECLI_BROWSER_PROFILE`.
  The profile is dedicated, so the user's daily browser is untouched and logins
  persist across restarts.
- Debugger: prefers the standard CDP ports `127.0.0.1:9222`, `9223`, `9224` and
  `9225`, then `9334`; the chosen port is saved in the profile. Override with
  `CECLI_BROWSER_CDP_PORT`. Under WSL, a Windows `chrome.exe` is reached through
  the Windows host address.
- Window mode: `CECLI_BROWSER_WINDOW_MODE=auto|offscreen|minimized|headless|hidden|visible`.
  `auto` hides the window on WSL when X11 is available: WSLg ignores window
  positions and does not honor `--start-minimized`, so the bridge launches a
  windowed browser and unmaps its top-level windows instead. Without X11 it
  falls back to headless. Other Linux desktops minimize, and macOS and Windows
  stay off-screen. A user-supplied `CECLI_BROWSER_BIN` keeps the off-screen
  default. Headless uses `--headless=new`; CDP screencast and input behave the
  same. Minimized adds `--start-minimized` and retries xdotool iconify when
  available. Hidden is windowed plus a per-second X11 unmap watchdog, so it
  keeps a normal browser fingerprint while staying off the desktop. Hidden
  only applies to a browser this bridge launched; attaching to an existing
  browser leaves its window state untouched.
  The mode is resolved per launch and persists no window setting; attaching to
  an existing browser leaves its window state untouched.
- Launch: detached with `--remote-debugging-port`, `--user-data-dir`,
  `--no-first-run`, `--no-default-browser-check`, the window flags for the
  resolved mode, and the background-throttling disable flags, then `about:blank`.
  On Linux the launched browser also dies with the bridge, including an abrupt
  SIGKILL; attaching to an already-running browser leaves that browser alone.
- The same page target is reused across calls. `Page` and `Runtime` are enabled
  on attach, and one shared screencast runs while at least one stream client is
  connected. JPEG frames are quality 70, acked at about 25 fps, capped at
  2048x2048, and the last frame is replayed to late subscribers.
- The page is emulated at up to four times the panel's CSS size, uniformly
  scaled down to stay within a 1920x1080 page viewport, so the page always fills
  the pane without exceeding 1080p.
  The canvas has its own 50%-300% client-side zoom; wheel input is forwarded to
  the page and, once the page reaches a scroll boundary while zoomed, native
  scrolling pans the canvas and then chains to the surrounding containers.

| Method | Path | Body | Response |
|--------|------|------|----------|
| GET | `/api/browser/state` | - | 200 `{ok, available, running, browser, executable, windowMode, profile, port, cdpUrl, url, title, error, viewport, frames, subscribers}` |
| POST | `/api/browser/start` | `{}` | 202 `{ok, ...snapshot}`; 503 if no browser |
| POST | `/api/browser/open` | `{url}` | 200 `{ok, ...snapshot}`; 400 empty/invalid; 503/409 if no browser |
| POST | `/api/browser/action` | `{action: "back"|"forward"|"reload"|"stop"}` | 202 `{ok}`; 400 unknown action |
| POST | `/api/browser/viewport` | `{width, height, dpr}` | 202 `{ok}`; 400 bad values |
| POST | `/api/browser/input` | `{event}` | 202 `{ok}`; 400 bad event |
| POST | `/api/browser/tab/new` | `{url?}` | 202 `{ok, ...snapshot}`; 400 bad url |
| POST | `/api/browser/tab/close` | `{tabId}` | 202 `{ok, ...snapshot}`; 404 unknown tab |
| POST | `/api/browser/tab` | `{tabId}` | 202 `{ok, ...snapshot}`; 404 unknown tab |
| GET | `/api/browser/stream` | - | SSE frame stream |

`viewport` is `{width, height, dpr}`. Bare domains become `https://`; `http(s)`,
`localhost`, loopback and `about:` addresses are preserved.

Snapshots include `tabs` (`[{id, title, url, active}]`), `activeTabId`, and the
page `scroll` metrics (`{x, y, maxX, maxY}`) used for wheel chaining. The bridge
polls the debugger every 1.5 seconds while it runs, so tabs opened by
browser-harness or the user appear without a reload; `POST /api/browser/tab`
switches the shared screencast to one of them. The desktop canvas can also be
zoomed client-side without changing the emulated page viewport.

Input events accepted by `POST /api/browser/input`:

- `{kind: "mouse", type: "mousePressed"|"mouseReleased"|"mouseMoved", x, y, button, clickCount, buttons}`
- `{kind: "wheel", x, y, deltaX, deltaY}`
- `{kind: "text", text}`
- `{kind: "key", type: "keyDown"|"keyUp", key, code, modifiers, text}`

Modifiers may be a bitmask or a list of `alt`, `ctrl`, `meta` and `shift`
(Alt=1, Ctrl=2, Meta=4, Shift=8).

`GET /api/browser/stream` uses `Content-Type: text/event-stream`,
`Cache-Control: no-cache`, keep-alive and `retry: 2000`. On connect it sends
`data: {"type":"state","state":{...snapshot}}`, then
`data: {"type":"frame","data":"<base64 jpeg>","meta":{...}}`, and
`data: {"type":"error","message":"..."}` on failures. A `: ping` comment goes
out every 15 seconds. The subscriber is removed when the connection closes, and
the final subscriber stops the shared screencast.

`POST /api/background` with `{bridgeId?, action: "list"}` returns
`{ok, commands}`; with `{bridgeId?, action: "output", key}` it returns
`{ok, output, command}`. Both call the agent's `cecli/background` extension.
The WebSocket channel exposes the same operations as `background.list` and
`background.output`.

For a manual check against the installed browser, run
`python3 desktop/scripts/browser_smoke.py`; it uses a scratch profile, verifies
frames and input, and always shuts its browser down.

## Terminal panel

The right workbench has a collapsed-by-default `Terminal` panel with two modes.
Logs mode renders the existing SSE `log` events (child stderr and non-JSON
stdout warnings) through xterm.js and a 2,000-line UI ring. Shell mode is a
per-workspace shell; it is available by default on a loopback bind and
can be disabled with `--no-terminal` or `CECLI_DESKTOP_TERMINAL=0`.

- ACP stdin/stdout stay on their pipes. The terminal is a separate process with
  `cwd` set to the workspace. POSIX hosts use a `$SHELL -i` PTY with its own
  process group, so sudo prompts and interactive commands work. Other hosts use
  a line-oriented pipe shell (`%COMSPEC%`/cmd.exe) where stdin can answer
  ordinary prompts but there is no resize, job control, or TUI support.
- `--terminal-shell` / `CECLI_DESKTOP_TERMINAL_SHELL` overrides the shell;
  `--no-terminal` / `CECLI_DESKTOP_TERMINAL=0` disables it.
the existing WS helpers. Binary frames are `[uint64 big-endian seq][raw PTY
bytes]`; text frames are JSON `ready`, `reset`, `exit`, `error`; client text
`{type:"input",data}` and `{type:"resize",cols,rows}` (binary input is also
accepted). Replay is a 256 KiB ring; `since` older than the ring returns
`reset` followed by the current buffer.
- Controls: `GET /api/terminal/state?bridgeId=...`, `POST /api/terminal/start`,
`stop`, `input`, `resize` (`{bridgeId, data|base64}`, `{bridgeId, cols, rows}`).
`GET /api/terminal/stream` is the read-only SSE fallback.
- `terminal` appears in `/api/state` as `{enabled, available, running, seq,
cols, rows, shell, bridgeId}` and is updated by the panel.
- Security: off by default; forced off for non-loopback binds; token required on
the WS; input is never logged or persisted; the UI only sends input while the
Shell tab is active. Agent-initiated `sudo` prompts are not answerable through
ACP stdin; users type into the PTY shell instead.

## Workspaces and onboarding

The desktop shell loads one session per folder listed in `~/.cecli/desktop.yml`:

```yaml
folders:
  - path: /abs/path
    name: Display Name
    enable_on_startup: true
```

Workspace entries live in `~/.cecli/desktop.yml` as a top-level `folders` list,
kept separate from the CLI config; writes go there atomically and preserve every
unrelated key. Legacy `desktop.folders` lists in `~/.cecli/conf.yml` or the
project-local `<workspace>/.cecli/conf.yml` are read only when desktop.yml has no
folders. Other settings still merge global then project (project wins).
`CECLI_DESKTOP_CONF_FILE`, `CECLI_DESKTOP_GLOBAL_CONF`, and
`CECLI_DESKTOP_FOLDERS_FILE` override those paths (used by tests). When no
folders are configured the server starts with zero sessions; `--workspace` only
establishes the allowed root and default cwd, it does not auto-open a session.

| Method | Path | Body | Response |
|--------|------|------|----------|
| GET | `/api/workspaces` | - | `{ok, workspaces, configPath, desktopConfigPath, globalConfigPath, projectConfigPath}` |
| POST | `/api/workspaces` | `{path, name?, enable_on_startup?}` | 201 `{ok, workspace, bridgeId, sessions}` |
| POST | `/api/workspaces/update` | `{path, name?, enable_on_startup?}` | 200 `{ok, workspace, bridgeId, sessions}` |
| DELETE | `/api/workspaces` | `{path}` | 200 `{ok, closed, sessions}` |

Each workspace entry carries `valid`, `error?` and the live `bridgeId` when its
session exists. Removing the primary workspace keeps its session until restart;
non-primary workspaces are closed.

GUI onboarding mirrors the TUI wizard: keys are written to `~/.cecli/.env`,
the model to `~/.cecli/conf.yml`, and running children restart so they pick up
the new environment.

| Method | Path | Body | Response |
|--------|------|------|----------|
| GET | `/api/onboarding/status` | - | `{configured, requires_onboarding, model, provider}` |
| GET | `/api/onboarding/providers` | - | `{providers}`; `?slug=` adds `{provider, models}` |
| POST | `/api/onboarding/config` | `{provider, model, api_keys?}` | `{configured: true, provider, model}` |
| GET | `/api/onboarding/copilot` | - | `{configured, models, login, token_dir, ...}` |
| POST | `/api/onboarding/copilot/login` | `{}` | device-flow `{state, verification_uri, user_code}` |

GitHub Copilot has no API key: `configured` is derived from its OAuth token

Snapshots and `details` events include:

```json
"usage": {
  "cost": 0.01,
  "tokens_sent": 120,
  "tokens_received": 30,
  "tokens_cached": 0,
  "cache_hit_ratio": 0.0,
  "context_used": 120,
```

## Multi-session extensions

The server owns `SessionManager`; each parent is an `AcpBridge` with its own
`cecli --acp` child. `bridgeId` identifies a parent, while `sessionId` is the
ACP coder id inside one bridge. Children may reuse JSON-RPC ids, so client-side
permission keys are `bridgeId:requestId`.

All mutation routes accept `bridgeId`; when more than one session exists it is
required (400 otherwise). Relevant additions:

| Method | Path | Body | Response |
|--------|------|------|----------|
| GET | `/api/sessions` | - | `{sessions, activeBridgeId, maxSessions}` |
| GET | `/api/state?bridgeId=...` | - | one bridge snapshot plus `sessions` |
| POST | `/api/sessions` | `{cwd?, title?}` | 201 `{bridgeId, state}` |
| POST | `/api/sessions/close` | `{bridgeId}` | 200 `{sessions}` |
| POST | `/api/complete` | `{bridgeId?, text}` | 200 `{suggestions, descriptions, start}` |
| GET | `/api/history?bridgeId=...` | - | `{messages, subagents}` conversation replay |
| POST | `/api/details` | `{bridgeId}` | snapshot with registry lists |
| POST | `/api/subagent/message` | `{bridgeId, sessionId, text}` | 200 `{result}` |
| POST | `/api/subagent/cancel` | `{bridgeId, sessionId}` | 202 |
| POST | `/api/skills|mcp|workflows|context` | `{bridgeId, action, name, ...}` | 200 `{result}` |

Snapshots add `bridgeId`, `primary`, `title`, `activity`, `activityDetail`, `subagents`,
`detailsSupported`, `skills`, `mcpServers`, `workflows`, `contextFiles`, and
permission entries tagged with `bridgeId`. SSE `status`, `session`, `update`,
`permission`, `details`, `subagents`, and `sessions` events also carry `bridgeId`.
The primary parent cannot be closed, and a busy parent cannot be closed.
Workflow runs execute as `/workflows run <name>` in the primary session rather
than as a separate child session.

`GET /ws` is an RFC6455 command channel. The handshake requires the
`cecli.desktop.v1` subprotocol and, when a token is configured, a
`token.<token>` subprotocol. Client frames are `{id, command, params}`; server
frames are only `{id, ok, result}` or `{id, ok: false, error, status?}`. No state
events are pushed over WebSocket: SSE is the sole server-to-client event stream.
Commands: `state.get`, `sessions.list|create|close`, `session.prompt|cancel|new|config|permission`,
`state.details`, `subagents.list|message|cancel`, `skills.list|load|remove|include|exclude`,
`complete.get`, `history.get`, `mcp.list|connect|disconnect`, `workflows.list|run`,
`context.add|remove`.

When the bridge starts, navigates, or reattaches to its browser, it calls the
`cecli/browser` ACP extension on every ready session with `{"cdpUrl", "port",
"url"}`. That updates `cecli/helpers/browser.py` so browser-harness reuses the
workbench browser instead of launching another one. The extension is re-sent only
when the CDP endpoint changes, and new sessions receive the current endpoint once
ready.
